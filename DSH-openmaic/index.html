DeepSeek Harness 插件开发实战课程

以 dsh-openmaic 为案例，从零带你开发一个 DeepSeek Harness 插件。

创建者: 标叔（整理自 dsh-openmaic 实战复盘 + 源码深读）
为谁创建: 想学会 dsh 插件开发、能独立为 dsh 贡献工具/技能/前端能力的开发者
基于: DeepSeek Harness v0.1-rc（developer preview）、dsh-openmaic 开源项目
最后更新: 2026-09-01
适用场景: 系统学习 dsh 插件开发，从零写出带工具、技能、前端渲染的完整插件

免责声明：dsh 处于 developer preview，官方明确后续会有破坏性变更。本书基于公开资料与 dsh-openmaic 仓库源码编写，落地前请以官方文档为准；不构成生产部署建议。

阅读指南

这是一本「教学书」，不是功能清单。目标只有一个：你读完能独立开发一个 dsh 插件，包含工具、技能、前端渲染、构建与发布。

dsh-openmaic 是一个给 dsh 增加「在线课堂制作能力」的开源插件：AI 助手装上它，就能生成教学卡片、互动组件、幻灯片，甚至调用外部服务生成整堂在线课。

分段章节你获得什么
Part 1 基础第 0–2 章理解 dsh 哲学，搭好环境，初始化插件项目
Part 2 核心能力第 3–7 章工具开发、契约模块、系统提示、技能开发
Part 3 进阶第 8–10 章HTTP 客户端、前端渲染、构建打包
Part 4 工程化第 11–15 章测试、调试、发布、实战案例、插件选型

读法建议：新手从第 0 章顺读；有 dsh 基础可直接跳到第 4 章开始动手。每章末尾有「动手练习」和「本章小结」。

第 0 章 开课准备・先听懂概念

在写任何代码之前，先用 30 分钟把 "DeepSeek Harness 是什么、插件是怎么回事" 这层窗户纸捅破。

0.1 这门课能让你学会什么

学完你将能独立完成：看懂 dsh-openmaic 项目结构；从零初始化 dsh 插件；给插件添加工具（Tool）；给插件添加技能（Skill）；让工具在聊天界面渲染出漂亮卡片；配置构建、测试，把插件打包发布。

一句话目标：让一个只会「打字」的 AI 助手，装上你的插件后学会「做卡片、做幻灯片、做互动小游戏」。

0.2 DeepSeek Harness 到底是什么

DeepSeek Harness（dsh）是 DeepSeek AI 开发的开源 agent harness（智能体运行框架）。采用「万物皆插件」架构，底层由 Cordis 框架驱动。

类比：dsh 是 AI 员工的「工作台 + 工具箱」，插件是装进工具箱的「新能力包」。

0.3 核心哲学：everything-is-a-plugin（万物皆插件）

dsh 里几乎每一块能力本身就是「一个插件」：模型适配器、工具、会话管理、UI 界面……全是插件。好处：可以换、可以组合、可以扩展。dsh-openmaic 就是给 dsh 增加「教学能力」的插件。

0.4 关键术语表

插件（Plugin）= 可插拔的代码包；工具（Tool）= AI 可调用的动作；技能（Skill）= 教 AI 按规范做的说明书；Toolview = 前端渲染组件；Cordis = 底层插件框架。

0.5 需要的工具链

Node.js（LTS）、pnpm、git、TypeScript、VS Code。dsh 目前是 developer preview，迭代很快。

0.6 案例全景：dsh-openmaic

dsh-openmaic 插件贡献了：4 个工具（openmaic_generate / render / widget / slide）、4 个技能（创作契约）、4 段系统提示、4 个 Toolview 前端组件。本书全程以它为活案例。

第 1 章 搭好开发环境

1.1–1.7 环境搭建

安装 Node.js → pnpm → 获取 dsh 源码 → 构建 → 运行验证。认识 dsh 源码结构（三个最重要目录：packages/、apps/、plugins/）。了解为什么插件开发需要一份 dsh 源码 checkout（类型定义、本地调试、依赖链接）。预习 dsh-openmaic 项目骨架。

第 2 章 初始化一个插件项目

2.1 插件项目的最小目录骨架

src/node/（Node 端源码）、src/client/（浏览器端源码）、lib/（编译产物）、package.json、dsh.plugin.json、tsconfig.json + tsconfig.client.json。

2.2 package.json：插件的身份证 + 说明书

四个关键字段：name（npm 包名）、main（Node 入口）、client（浏览器入口）、dsh.plugin（插件声明）。

2.3 dsh.plugin.json：插件清单（旧格式）

声明插件名、入口、依赖服务的清单文件。dsh 加载时读取。

2.4 cordis.patch.yml：把插件插进 dsh

通过 patch 机制把插件注册到 profile 的插件栈里。

2.5 双 tsconfig：Node 端和浏览器端分开编译

Node 端 target ES2022 / module NodeNext；浏览器端用 tsconfig.client.json 编译为浏览器可执行代码。

2.6 你的第一个插件：Hello World 工具

导出 name + apply(ctx)，用 ctx.tools.register(defineTool({...})) 注册一个 greet 工具。逐行解读。

2.7 怎么把插件装进 dsh 验证

两种方式：cordis.patch.yml 临时插入 web profile；或把编译好的 lib/ 复制到插件目录。

第 3 章 理解 Cordis：插件生命周期

3.1–3.5 生命周期详解

Cordis 是 dsh 底层的插件框架。插件通过 apply(ctx) 启动，ctx.effect() 注册可逆副作用（插件卸载自动清理），inject 声明服务依赖。三大核心服务：ctx.tools（工具注册）、ctx.skills（技能注册）、ctx.systemPrompt（系统提示注入）。生命周期：加载 → 依赖解析 → apply → 运行 → 卸载（dispose）。

第 4 章 开发第一个工具：openmaic_render

4.1 一个工具由哪四样东西组成

name（工具名）、description（描述）、parameters（参数 schema）、output（输出规范）。

4.2 defineTool：工具的模板

defineTool 收窄参数类型、校验入参、按 output.schema 推导返回类型。

4.3 参数（parameters）：告诉模型怎么填

用 zod schema 定义参数结构，含类型、描述、是否必填。

4.4 输出（output）：结果如何返回给模型

定义 schema + render 函数，输出可以是文本、卡片、混合内容。

4.5 presentationMeta：把内容交给前端的暗号

工具结果附带的持久化数据，前端 Toolview 据此渲染。

4.6 错误处理：让工具优雅地失败

结构化错误（UNKNOWN_TOOL 等），调用失败但不终止轮次，模型自决重试或换路。

4.7 完整对照：dsh-openmaic 的 openmaic_render

完整源码解读，从参数定义到输出渲染的全流程。

第 5 章 共享契约模块：纯函数设计 + TDD

5.1–5.4 契约模块与测试

「共享契约模块」是 Node 端和浏览器端共同依赖的数据结构与校验逻辑。fragment.ts 包含工具名常量、meta 接口、校验规则、字节数计算、核心校验函数。slide 和 widget 的契约模块复用相同模式。TDD：先写测试再写实现，确保双端一致性。

第 6 章 系统提示注入：教模型用你的工具

6.1–6.5 教模型用工具

工具需要被「教」—— 通过 ctx.systemPrompt.section() 注入使用说明。order 控制段落顺序。什么时候用系统提示 vs 什么时候用技能：系统提示是「固定入职培训」，技能是「按需查阅的手册」。

第 7 章 技能（Skill）开发：写「给 AI 的说明书」

7.1–7.5 写 AI 说明书

技能 = 可选的指令（SKILL.md 文件），不是插件、不是会话事件。三个核心类型：SkillCandidate / SkillProvider / SkillDefinition。注册技能和注册工具一样在 apply 里。模板系统把长规范拆到单独文件。dsh-openmaic 的四个创作契约（render / widget / slide / teach）。

第 8 章 HTTP 客户端工具：openmaic_generate

8.1–8.5 调用外部服务

openmaic_generate 调用外部服务生成整堂在线课。可测试的 fetch 客户端（把 fetch 变成可注入参数）、Cookie 处理、状态机（三种终态 + 清晰错误）、配置项调节工具行为。

第 9 章 浏览器端渲染：Toolview / 沙箱 / 流式预览

9.1–9.4 前端渲染体系

为什么需要浏览器半边：工具执行在 Node 端，但渲染在浏览器。注册 Toolview（前端组件），React 组件读取 meta 数据渲染。沙箱文档的组装（shell.ts），流式预览机制。

第 10 章 构建与打包：tsdown 双端

10.1 tsdown 双端构建

tsdown 构建工具：Node 端 + 浏览器端分开编译。require 白名单检查、禁止动态 import()、禁止多 chunk。定位 dsh checkout 的反向解析。

第 11 章 测试：从纯函数到集成

11.1 纯函数到集成

契约模块纯函数测试、工具执行测试、集成测试。测试驱动开发确保双端一致性。

第 12 章 调试、常见坑与发布

12.1 调试与发布

常见坑：inject 漏声明、tsconfig 不匹配、cordis.yml 被重写、白名单检查失败。发布流程：npm publish + GitHub Release。

第 13 章 实战案例集

13.1 四个工具 + 四个技能逐个上手

openmaic_render（教学卡片渲染）、openmaic_widget（互动组件）、openmaic_slide（幻灯片）、openmaic_generate（外部服务生成课堂）。每个工具配对应技能（创作契约）。

第 14 章 端到端全流程演示

14.1 一次「光的折射」微课从头走到尾

从用户输入「帮我做一堂光的折射微课」→ 模型调用 skill → 调工具 → 生成卡片/组件/幻灯片 → 浏览器渲染的完整流程演示。

第 15 章 四种插件开发方法：学会选型再动手

15.1–15.11 插件开发全景

四种插件类型：Model Provider（模型适配器）、Event Interceptor（事件拦截器）、Tool Plugin（工具插件，dsh-openmaic 的主干）、Agent Loop（高阶）。决策表 + 配置三层叠加（Preset → Bundle → Patch）。调试技巧 + 综合实战（加审批拦截器）。
